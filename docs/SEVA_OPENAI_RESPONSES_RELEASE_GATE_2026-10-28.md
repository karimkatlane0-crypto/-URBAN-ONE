# URBAN ONE / SEVA — OpenAI Responses release smoke gate (28 October 2026)

**Scope:** safe, explicit provider smoke check. A source-code test, local mock pass or Vercel static page does **not** prove a live authenticated SEVA AI response.

## Configuration and execution

Use a **trusted, isolated server runtime** with network egress to the official `https://api.openai.com/v1/responses` endpoint and a funded OpenAI API project. Configure `OPENAI_API_KEY` using the hosting provider's secret manager; never paste it in chat, commit it in GitHub, include it in a frontend bundle, or print it in logs. Explicitly set `OPENAI_MODEL` to a model actually available in that API project.

Run `npm run smoke:openai` from the repository root inside that runtime. This makes **one** Responses API request, so it should only be run with an approved budget. It sends only the fixed prompt `Reply with exactly: URBAN_ONE_OPENAI_OK` and `store:false`, with a 30-second timeout. No private goals, students, messages, Lastre CRM or payment data are transmitted.

The test accepts only the official API origin. Loopback HTTP URLs may be used **only** when `NODE_ENV=test` for a local synthetic mock test. Do not set `NODE_ENV=test` in live deployment to bypass origin protection.

## PASS evidence

A successful result must include all of:
- HTTP success from the provider, expected output token `URBAN_ONE_OPENAI_OK`, and a nonempty provider `responseId`.
- Effective API model, redacted timestamp, release commit and environment (staging/production).
- No secret or raw provider payload in stored artifacts.

Record the nonsecret response ID in a private evidence log. A response ID generated by a **mock** is not evidence of real OpenAI inference.

Run source tests in CI with `node --test tests/openai-smoke.test.mjs`; they use synthetic credentials only and make no real OpenAI requests.

## Independent NO-GO conditions

1. **Backend:** actual HTTPS URL running Node, authenticated session, durable SQLite volume, tenant isolation, restart and offsite backup/restore tested.
2. **User inference:** authenticated user consent and entitlement; real `/api/ai/generate` response and provider trace ID inside SEVA, not just this standalone provider smoke.
3. **Financial:** sales, Stripe callbacks and bank transfer order processing remain disabled unless separately verified, reviewed and activated.
4. **App releases:** Android Play AAB production signing, Data Safety and Play Console review are independent gates.

If any of these are unverified, the commercial release remains **NO-GO**. No hosting plan or API funds are created by this document.
