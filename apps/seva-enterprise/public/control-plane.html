02 / CONFLICT RESOLUTION

Conflitti di sistema da risolvere

Ordine di correzione basato sulle dipendenze tecniche.

01 · Entry point duplicati

Studio Enterprise, Unified Studio e CRM Studio convivono. Soluzione: un solo ingresso canonico; migrare le funzioni e le route dopo test, senza cancellare le pagine esistenti prima della parità funzionale.

02 · Vercel non allineato a GitHub

Il progetto esiste ma non mostra repository collegato. Soluzione: associare una pipeline preview controllata, fissare commit e root directory, verificare build e route prima di qualsiasi promozione.

03 · Frontend statico vs backend persistente

Gli endpoint di salute sono 404 e non esistono env visibili. Soluzione: frontend Vercel separato da API HTTPS persistente, PostgreSQL/RLS, secret manager, audit, backup e restore; niente credenziali nel browser.

04 · CRM e lifecycle identity

SYNAPSY è master; Klaviyo è downstream. Soluzione: ID opaco stabile, tenant isolation, ledger consenso, sync unidirezionale, idempotenza e cancellazione propagata.

05 · CMS e canali esterni

WordPress connector mismatch; Spotify non connesso. Soluzione: riconciliare host e identità, staging WordPress, Embed ufficiale e OAuth Spotify minimo separato.

06 · Dati, analytics e attribuzione

Power BI è solo preparato; affiliazioni senza prova di settlement. Soluzione: definire KPI, collegare workspace/gateway, distinguere click, ordine, commissione approvata e pagamento.

07 · Kubernetes e resilienza

Cluster non identificato. Soluzione: inventario autorizzato, namespace staging, ingress/TLS, RBAC, secrets, logs/metrics, backup/restore, rollback e attestazione immagine.

08 · Privacy e accessi

Drive e contatti hanno autorizzazioni separate. Soluzione: accesso per account e finalità, consenso individuale revocabile, nessuna copia globale o sincronizzazione automatica.

03 / RELEASE ENGINEERING

Sequenza di rilascio

Ogni fase produce evidenza ispezionabile; nessuna fase si auto-certifica.

BUILDConsolidare route, API, UI e manifest
VERIFYTest, CI, browser, sicurezza e dati
STAGINGVercel preview + backend isolato + Kubernetes
CERTIFYReviewer indipendente, restore e provider E2E
RELEASEGO esplicito, rollback pronto, rollout controllato
Decisione corrente: NO-GO produzione. La versione Vercel production non è stata pubblicata né modificata. Il prossimo gate utile è collegare in modo verificabile il repository alla preview e ripristinare un backend HTTPS persistente prima di abilitare provider o analytics live.
